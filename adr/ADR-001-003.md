# ADR-001: SQL Server is the primary enterprise reference

## Decision

ATLAS treats Microsoft SQL Server as the first-class enterprise source and target reference. PostgreSQL, files, and SFTP are adapter boundaries.

## Rationale

The reference scenario includes legacy banking data, T-SQL, stored procedures, locking, deadlocks, isolation levels, and SQL Server CDC/change mechanisms. Keeping SQL Server explicit prevents a generic file-only demo from implying enterprise database competence.

## Consequence

The repository includes SQL Server schemas and labs. The local Python demo remains database-independent because SQL Server is not assumed to be available in every development environment.

# ADR-002: CDC is at-least-once; targets are idempotent

## Decision

CDC ingestion and delivery are documented as at-least-once. Events have stable IDs, are deduplicated before replay, and target writes use idempotency keys. Reconciliation is the correctness authority.

## Rationale

Exactly-once is not a safe slogan for a distributed system without a complete end-to-end proof. Explicit at-least-once semantics make duplicates and recovery paths testable.

# ADR-003: Checkpoints are durable evidence, not offsets alone

## Decision

A checkpoint stores migration, job, table, partition, batch, source position, CDC offset, target state, checksum, worker, migration version, and timestamp.

## Rationale

An offset alone cannot explain what was committed or prove that a resumed batch corresponds to the same transform and dataset version. The richer record supports replay and incident investigation.
